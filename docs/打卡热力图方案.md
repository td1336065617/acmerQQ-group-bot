# acmerQQ群机器人：战绩卡「近 12 个月打卡热力图」方案

> 版本：v1（待实施）
> 目标版本：1.8.0
> 需求确认：要做 GitHub/CF 同款**提交热力图**；范围 **Codeforces + AtCoder**；
> 实施完成后**必须核对渲染效果**（防重叠/越界/压住下方图表）。

---

## 1. 需求

在个人战绩卡中新增一块「**近 12 个月打卡**」热力图：

- 形态：7 行（周一~周日）× 最多 53 列（周），每格代表一天；
- 着色：按当天提交数分 5 档（`0 / 1-2 / 3-5 / 6-10 / 10+`），0 用浅灰；
- 附带 streak 指标：`一年活跃 N 天`、`当前连续 X 天`、`最长连续 Y 天`；
- 平台范围：**Codeforces**、**AtCoder**；牛客/洛谷暂不支持（见 §2.3）；
- 展示位置：资料卡中「难度分布」「rating 趋势」等图表同区域（`profile-meta`）。

---

## 2. 数据可行性与来源（已实测）

### 2.1 Codeforces ✅ 数据已在手

`user.status` 每条记录带 `creationTimeSeconds`，现有分析已用它统计
`active_days_30 / active_days_90`（`_build_cf_analysis`）。

实测（2026-09-12）：

| 账号 | 首页 1 万条覆盖跨度 | 一年内有提交的天数 |
| --- | --- | --- |
| `maspy`（21459 条） | **1080 天** | 236 天 |
| `Benq`（8574 条，全部） | 4078 天 | 65 天 |

**结论**：单页 1 万条通常已覆盖 >1 年，**热力图不产生额外网络请求**。
仅在极端情况下（一年内提交 >1 万条）才需要多翻一页，见 §3.3。

### 2.2 AtCoder ✅ 可行（需复用现有翻页）

kenkoooo 提交记录字段：`epoch_second / problem_id / result / language ...`，
自带秒级时间戳。分析路径本就会翻页到 `ATCODER_SUBMISSION_SCAN_LIMIT=20000`，
热力图直接复用这批记录即可。

实测：`tourist` 公开记录 1630 条 / 4 页 / 9.8s（含题目模型），代价可接受。

### 2.3 牛客 / 洛谷 ❌ 暂不支持

两平台的公开页面/接口只返回**聚合统计**（通过题数、难度分布等），
**没有逐条提交时间戳**，无法构建按天热力图。
因此这两个平台保持现状（仅展示 `近30天活跃` 这类已有指标），
卡片上不显示热力图。

## 3. 数据层设计

### 3.1 数据结构

```python
# 放在 profile.analysis / profile.extra 中，随现有 12 小时分析缓存一起缓存
activity_daily: Dict[str, int]      # "2026-09-12" -> 当天提交数（仅近 365 天）
activity_summary: {
    "active_days": int,   # 一年内有提交的天数
    "current_streak": int, # 当前连续打卡天数（截至今天/昨天）
    "longest_streak": int, # 一年内最长连续天数
    "weeks": int,          # 实际渲染的周数（<=53）
}
```

### 3.2 聚合规则

- **时区**：统一按 **北京时间（CN_TZ）** 分日，与卡片其它时间字段一致；
- **计入范围**：近 365 天（含今天），更早的记录丢弃；
- **计数口径**：当天**提交条数**（与 CF 图的"提交活动"一致，不去重题目）；
- **连续天数**：
  - `current_streak`：从今天（或昨天，若今天尚未提交）向前连续有提交的天数；
  - `longest_streak`：一年窗口内最长连续段；
- 数据不足（如新账号仅几天数据）时仍正常渲染，只是格子稀疏。

### 3.3 覆盖度保证（CF 极端情况）

若首页 1 万条中**最早时间仍在 365 天以内**，说明一年内提交超过 1 万条，
此时再翻一页（复用 `_cf_scan_submissions` 的翻页逻辑，最多到现有上限），
直到覆盖满 365 天或触达上限；触达上限时按"已覆盖范围"渲染，
并在图例旁标注实际覆盖区间（例如"近 8 个月"）。

## 4. 渲染设计

### 4.1 HTML 路径（有 Chromium 时）

```html
<div class="activity-heatmap">
  <div class="activity-title">近 12 个月打卡</div>
  <div class="activity-grid" style="--weeks:53">
    <!-- 每列一周，7 个 .cell；level-0..level-4 决定底色 -->
  </div>
  <div class="activity-legend">少 ▢▢▢▢▢ 多 · 一年活跃 236 天 · 当前连续 12 天</div>
</div>
```

- CSS：`display:grid; grid-template-rows:repeat(7, 1fr); grid-auto-flow:column;`
  单元格用 `border-radius:3px`，颜色由平台 `--accent` 派生；
- 宽度自适应：单平台卡 53 列；双平台卡降级为 **26 周**（见 §4.4）。

### 4.2 Pillow 路径（回退）

新增 `_pillow_activity_heatmap(draw, profile, x, y, width, fonts...) -> int`：

- 依据可用宽度算格子边长：`cell = min(14, (width - gap*(weeks-1)) / weeks)`，
  格间距 2px；最小格边长 3px，低于该值自动降级为更少周数；
- 逐格 `rounded_rectangle`，颜色按 5 档（0 档用 `#eee6ec` 之类的浅灰）；
- 左侧可选 3 个星期标签（周一/周三/周五，字号 11）与底部月份标签；
- 返回本图表占用的高度（含标题与图例），供上层累计 `meta_y`。

**高度必须被正确预留**：这是本次的关键回归点——1.6.1 刚修过"固定坐标导致
重叠"，新图表必须走同一套"先测量、再绘制、高度回传"的流程。

### 4.3 卡片高度联动

三处需要同步（否则会出现压字/裁切）：

| 位置 | 作用 |
| --- | --- |
| `_profile_card_height()` | 估算单卡总高，决定卡片矩形与画布高度 |
| `_pillow_profile()` 的 `card_rows` | 多平台时按最大卡高对齐 |
| `meta_count(profile)` | 元信息条数（本次新增"打卡热力图"1 条） |

### 4.4 双平台卡降级

双平台卡内容宽约 468px：53 列会被压到每格 ~6px，可读性差。
因此：

- 单平台卡（内容宽 1034px）：完整 **53 周** + 图例 + streak；
- 双平台卡：**26 周**（半年）紧凑版，仅图例省略，不显示月份标签；
- 若 26 周仍然过窄（<3px/格），则仅显示文字摘要
  （`半年活跃 N 天 · 当前连续 X 天`），不画格子。

## 5. 边界与降级

| 场景 | 行为 |
| --- | --- |
| 平台不支持（牛客/洛谷） | 不渲染该图表（保持现有卡片） |
| 无提交记录 | 不渲染，或显示"近 12 个月暂无提交" |
| 数据不足一年（新账号） | 正常渲染，格数按可用周数 |
| 时钟偏差/未来时间戳 | 忽略未来日期，不崩溃 |
| 扫描被上限截断（§3.3） | 按实际覆盖渲染并在图例标注覆盖区间 |
| HTML 与 Pillow 结果不一致 | 以同一份 `activity_daily` 数据渲染，禁止各自计算 |

## 7. 测试计划

### 7.1 数据层单测

- 按天聚合：跨午夜、跨月、跨年边界；
- 时区：UTC 时间戳落在北京时间的正确日期；
- 一年裁剪：366 天前的记录被丢弃；
- streak：连续段计算、断档、今天未提交但昨天提交（`current_streak` 正确）、
  一年内最长段；
- 覆盖度：模拟"一年内 >1 万条"时触发补翻页（mock `_cf_json`）。

### 7.2 渲染层单测

- HTML：包含 `weeks` 个列、每列 7 格、档位 class 与计数匹配；
- Pillow：**录制 `draw.text` / `rounded_rectangle` 调用**，断言
  - 格子数量 = `weeks*7`（或按可用周数）；
  - 所有格子的右边界 ≤ 卡片内容右边界、下边界 ≤ 卡片高度；
  - 图例文字不与格子区域重叠。

### 7.3 最终渲染核对（用户明确要求，必做）

1. 用**真实账号**渲染完整卡片：
   - CF：`maspy`（提交极多）、`Petr`（LGM+自定义头衔）、`ygy0`（数据少）；
   - AtCoder：`tourist`；
2. 录制全部绘制调用，**逐项核对坐标**：热力图区域与下方图表、卡片底边均不重叠；
3. 生成 PNG 并**裁剪热力图局部放大**，人工确认格子/图例/月份标签可读；
4. 分别验证 **单平台卡、双平台卡（降级 26 周）、数据不足** 三种形态；
5. 核对卡片总高：热力图加入后，卡片矩形、画布高度、多平台对齐都随之增长，
   不能出现内容溢出到卡片外。
