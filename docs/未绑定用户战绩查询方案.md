# acmerQQ群机器人：未绑定用户战绩查询 实现方案

> 状态：**已实现并部署（v1.6.0）**
> 目标版本：1.6.0
> 前提：不修改任何现有指令行为；新增指令与现有指令无冲突（已核查，见 §2）
>
> **需求确认结论（已拍板）**
> 1. 指令形式：`查询cf <账号>`，兼容 `查询 cf <账号>`（带空格）与 `查cf` 简写；
> 2. 卡片详细度：**默认摘要版**，结尾加「详细」才抓难度分布/分析；
> 3. 绑定提示：**群聊加、私聊不加**；
> 4. 防滥用：**每用户 30 秒 1 次 + 每群每分钟 10 次**；
> 5. 牛客/洛谷：**接受**退化为数字 UID / 主页链接，四个平台都做；
> 6. 私聊：**允许**，与群聊共用同一套限流。

---

## 1. 需求

新增一个指令，**用平台用户名/UID 直接查询任意（未绑定）用户的战绩**，输出与现有
`@某人 查询战绩` 相同的资料卡（图片，渲染失败回退纯文本）。

典型用法：

```
查询cf td1336065617          → Codeforces 资料卡
查询atcoder tourist         → AtCoder 资料卡
查询牛客 12345678            → 牛客资料卡（数字 UID）
查询洛谷 123456              → 洛谷资料卡（数字 UID）
查询cf https://codeforces.com/profile/xxx   → 也支持主页链接
```

**不要求对方绑定**，不写入绑定关系，不加入群排行。

---

## 2. 指令冲突核查（已完成）

现有指令共 4 类匹配方式：

| 匹配方式 | 例子 | 与本功能是否冲突 |
| --- | --- | --- |
| 精确全匹配 | `查询战绩`、`我的cf`、`cf比赛`、`群cf排行`、`本周进步榜`、`acm菜单` | ❌ 不冲突（`查询cf xxx` 不是精确匹配） |
| 正则前缀：绑定 | `^绑定\|bind\s*(平台)\s+(.+)$`（`ACCOUNT_BIND_RE`） | ❌ 前缀不同 |
| 正则前缀：确认/解绑 | `^确认绑定...`、`^解绑...` | ❌ 前缀不同 |
| mention 分支 | `@某人 战绩` / `@某人 查询战绩` | ❌ 不含 @ 时不进入 |

**结论**：`查询<平台> <标识>` 作为新的正则前缀指令，与现有指令**无冲突**。
（唯一需要留意的是用户在群里发 `查询战绩` 仍走原精确匹配，含义不变。）

## 3. 平台能力矩阵（已实测）

| 平台 | 公开接口的标识要求 | 用户名查询 | 代码支持 |
| --- | --- | --- | --- |
| **Codeforces** | handle（`codeforces.com/api/user.info?handles=`） | ✅ 支持 | `normalize_account_identifier` 接受 handle / `/profile/xxx` |
| **AtCoder** | handle（`atcoder.jp/users/{handle}` + `/history/json`） | ✅ 支持 | 接受 handle / `/users/xxx` |
| **牛客** | **数字 UID**（`ac.nowcoder.com/acm/contest/profile/{uid}`） | ❌ 不支持 | 只接受 `\d+` / `/acm/contest/profile/\d+` |
| **洛谷** | **数字 UID**（`/user/{uid}`、`api/user/show?uid=`） | ❌ 不支持 | 只接受 `\d+` / `/user/\d+` |

实测证据（服务器直连）：

- 洛谷 `https://www.luogu.com.cn/api/user/search?keyword=xxx`
  → **无限 302 重定向到自身**（需登录态），公开不可用；
- 牛客搜索页 `https://www.nowcoder.com/search?...&type=user` → 301 跳转，非公开 API。

**所以：CF / AtCoder 支持用户名；牛客 / 洛谷只能 UID 或主页链接**（提示文案需说明）。

## 4. 实现设计

### 4.1 指令解析

新增正则（放在 mention 分支之后、绑定分支之前）：

```python
ACCOUNT_LOOKUP_RE = re.compile(
    r"^(?:查询|查|lookup)\s*"
    r"(cf|codeforces|nk|牛客|nowcoder|lg|洛谷|luogu|atc|atcoder)\s+"
    r"(.+?)\s*$",
    re.I,
)
```

- 平台别名复用现有 `normalize_platform()`（与绑定指令同一套别名）；
- 标识交给现有 `normalize_account_identifier(platform, value)` 归一化，
  自动支持「用户名 / UID / 主页链接」三种形态；
- 归一化失败时，按平台给出精确提示（见 §4.4）。

### 4.2 数据流（复用现有组件，无需新增抓取逻辑）

```
查询cf td1336065617
  └─ normalize_account_identifier("codeforces", "td1336065617") → "td1336065617"
  └─ account_fetcher.get_profile(                      # 不依赖绑定
         platform, identifier,
         detail=True, force=False,
         include_submissions=False,
         include_difficulty=True, include_analysis=True)
  └─ delta = account_fetcher.rating_delta_for_period(profile, days=7)
  └─ account_card_renderer（经 _render_profile_card）
         display_name = handle（标注「未绑定」）
         weekly_changes = {platform: delta}
         group_ranks = {}                              # 未绑定 → 无本群排名
  └─ 渲染失败 → _format_account_text(...) → _adaptive_results（纯文本兜底）
```

**复用点（均为现成函数）**：
`normalize_account_identifier` / `get_profile` / `rating_delta_for_period` /
`_render_profile_card` / `_format_account_text` / `_adaptive_results` /
`_account_error_text` / `platform_label` / `normalize_platform`。

### 4.3 与 `@某人 查询战绩` 的差异（必须有）

| 项 | `@某人 查询战绩` | 本功能 |
| --- | --- | --- |
| 数据来源 | QQ 用户的**绑定账号** | 指令里给的**用户名/UID** |
| 本群排名 | 展示 | **不展示**（未绑定、非群成员） |
| 本周变化 | 有 | 有（由 profile 自带 rating_history 计算） |
| 是否写入 Rating 快照 | 是（记录用户历史） | **否**（避免污染群排行/进步榜数据） |
| 标题 | `📊 xxx 的竞赛战绩` | `📊 td1336065617 的 Codeforces 战绩（未绑定）` |

### 4.4 错误与边界

| 场景 | 行为 |
| --- | --- |
| 标识格式不合法（如 CF 用了中文名） | 提示该平台要求的格式；牛客/洛谷额外说明"不支持用户名，请用数字 UID 或主页链接" |
| 用户不存在 / 平台 404 | 复用 `_account_error_text(platform, exc)`（含负缓存，短时间内不重复打接口） |
| 只给了 `查询cf` 没有标识 | 回复用法示例（不是静默无响应） |
| 平台网络失败/超时 | 复用现有错误文案（已有平台级区分） |
| 群聊中 @ 了人又带平台 | mention 分支优先，保持现有行为 |

### 4.5 防滥用（新增，必须）

现有机制：CF 2.1 秒全局限速、渲染全局信号量=1、负缓存。

**新增**：
1. **每用户冷却**：同一用户 30 秒内只能查一次（KV 记 `lookup_cd_<user_id>`）；
2. **每群频率**：同一群每分钟最多 10 次（KV 滑动窗口或计数+时间戳）；
3. 超限时回复"查询太频繁，请稍后再试（X 秒）"，不消耗抓取配额；
4. 命中 30 分钟资料缓存时不受冷却限制（成本为零，可放行）。

### 4.6 缓存与成本

- `get_profile` 自带缓存：摘要 30 分钟、详情 30 分钟、分析 12 小时（按标识 key）；
- 未绑定查询**不写** `rating_history`，因此不会影响群排行/进步榜；
- CF 走 2.1 秒全局限速；批量接口不适用于单人查询。

## 7. 实现落地（v1.6.0）

- 指令正则与常量：`ACCOUNT_LOOKUP_RE` / `ACCOUNT_LOOKUP_USAGE_RE` /
  `ACCOUNT_LOOKUP_DETAIL_RE` / `ACCOUNT_LOOKUP_USAGE_HINTS` /
  `ACCOUNT_LOOKUP_UID_ONLY` / `LOOKUP_*` 限流常量；
- 分发：`on_message` 中在解绑分支之后接入（不影响任何既有分支）；
- 业务实现：`_reply_account_lookup()` + `_account_lookup_usage()` +
  `_account_lookup_invalid_hint()` + `_lookup_rate_verdict()` +
  `_check_lookup_rate_limit()`；
- 菜单文案已加入该指令；
- 测试：`tests/test_account_lookup.py`（6 条用例，覆盖别名/空格/详细后缀/
  不误伤既有指令/平台能力边界/限流判定），全量 115 passed。

### 与 @查询 的语义差异（已实现）

- 未绑定查询**不写 Rating 快照、不参与群排行/进步榜**（避免污染数据）；
- 卡片不展示「本群排名」；
- 标题明确标注「（未绑定）」。

## 8. 已知限制

- 牛客/洛谷**无法用用户名**查询（公开接口需要数字 UID；洛谷搜索接口实测为
  无限 302，需登录态）；
- 首次查询某账号需真实抓取（CF 受 2.1 秒全局限速），命中 30 分钟资料缓存后很快；
- 「详细」模式会触发平台分析抓取，明显更慢，建议按需使用。
