## 1. 工作流骨架

```
每个批次（可独立提交）都走同一条流水线：

  P0 准备 ──► P1 纯逻辑 ──► P2 接线 ──► P3 单测 ──► P4 真机核对 ──► P5 收尾
  基线测试     新模块+单测    配置/调度/    文档列出的    线上数据端到端    配置表/CHANGELOG/
  记录 passed   (不接主线)    渲染/指令     用例全绿      一次              版本号(本地)
```

**准入 / 准出（Gate）**

| 环节 | 准入 | 准出 |
| --- | --- | --- |
| P0 准备 | 上一批次已收尾 | 全量测试基线记录（当前 192 passed）；docs 相关章节已读 |
| P1 纯逻辑 | — | 新模块可被单测独立驱动；不 import 主线；单测通过 |
| P2 接线 | P1 通过 | 配置 6 步（A）/ 5 步（B）齐全；WebUI 保存后立即生效 |
| P3 单测 | P2 完成 | 文档列出的用例全部落地且绿；既有用例无回归 |
| P4 真机 | P3 全绿 | 线上真实数据端到端跑通一次，记录"输入 → 实际输出" |
| P5 收尾 | P4 通过 | README/CONFIG/CHANGELOG/版本号（本地更新）；DoD 清单逐项打勾 |

**质量门（每批次必过）**
1. `pytest tests -q` 全绿（基线 192 例，只增不减）；
2. `ruff check --select F,E9` 无新增问题；
3. 涉及缓存口径/模型变更 → 版本号提升（`ANALYSIS_CACHE_VERSION` / `CARD_FORMAT_VERSION` / `CACHE_VERSION`）；
4. 新增幂等键：发送成功才写键，失败下一 tick 可重试；
5. 失败路径有 warning 日志，成功路径有 info 日志。

## 3. 阻塞与例外处理

| 情况 | 处理 |
| --- | --- |
| 后台探针（21:33 起）显示牛客名次延迟 | A-1 的 `settle_delay_minutes` 默认值调到"实测就绪时间 + 5 分钟"，其余不变 |
| 牛客名次始终不可得 | 触发文档既有降级：参赛名单版（`submit-list` 的 `signUpUsers`），卡片标注口径 |
| 真机核对失败（数据/接口变动） | 先补降级路径再继续，不留下"线上必崩"的代码 |
| 单批次内发现设计缺陷 | 就地修正实现文档对应小节（本地），并在该批次 DoD 中记录 |
