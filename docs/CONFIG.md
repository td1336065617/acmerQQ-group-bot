# acmerQQ群机器人 配置文档

## 1. 配置入口与存储位置

- **配置入口**：AstrBot 管理面板 → 插件管理 → **acmerQQ群机器人**
  （`pages/settings/index.html`）。
- **存储方式**：配置保存在 AstrBot 的插件 KV 存储（数据库）中，**不在插件
  目录写文件**，因此升级/重装插件不会丢配置。
- 存储键：

| 键 | 内容 |
| :--- | :--- |
| `admin_users` | 管理员 openid 列表 |
| `settings` | 全局推送设置（早报时间/平台/提醒/@全体） |
| `groups` | 各群配置（自动注册） |
| `reminded` | 已提醒的比赛去重记录 |
| `morning_<群ID>_<日期>` | 当日早报是否已发送 |
| `at_all_blocked_until_<群ID>` | @全体失败后的冷却截止时间 |

## 2. 配置项一览

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 管理员列表 `admin_users` | `[]` | 可执行 `/update` 的 openid 列表 |
| 每日早报时间 `settings.morning_push_time` | `08:00` | HH:MM（24 小时制） |
| 推送平台 `settings.push_platforms` | 牛客/CF/AtCoder/洛谷 | 早报与提醒默认平台 |
| 赛前提醒 `settings.reminder_enabled` | 开 | 开始前 15 分钟提醒 |
| 尝试 @全体成员 `settings.at_all_enabled` | 关 | 通知带 `<@everyone>`，失败自动降级 |
| 群启用 `groups[].enabled` | 开 | 是否向该群推送 |
| 群早报时间 `groups[].morning_push_time` | `08:00` | 覆盖全局时间 |
| 群推送平台 `groups[].push_platforms` | 全部 | 早报取“全局 ∩ 群”平台 |
| 群赛前提醒 `groups[].reminder_enabled` | 开 | 该群是否发送提醒 |

## 3. 管理员权限

- QQ 官方适配器不会把群主/管理员角色映射到 AstrBot 的管理员判断上，因此
  `/update` **必须**在 WebUI“管理员设置”里显式添加 openid，否则会提示
  “此指令仅限管理员”。
- 获取自己的 openid：在群里发一条任意消息，然后查看 AstrBot 日志中的
  `用户名/OPENID: 消息` 记录，斜杠前的就是 openid。

## 4. 推送行为

### 每日早报
- 到达配置时间后，汇总“当天开始”的已启用平台比赛并推送到各启用群。
- 当天没有任何比赛时**不推送**，并标记当天已检查，避免反复尝试。
- 同一群同一天只推送一次。

### 赛前提醒
- 比赛开始前 15 分钟窗口内发送提醒，按“平台+比赛ID”全局去重。
- 定时任务每 30 秒检查一次，配置修改后最多 30 秒内生效。

### @全体成员
- 开启后，早报与提醒会先尝试带 `<@everyone>` 发送。
- 若 QQ 返回失败（无权限），自动改发不带 @ 的普通通知，并把该群标记
  **6 小时内不再尝试**。
- 注意 QQ 官方机器人的 @全体成员能力受限（官方格式文档仅明确支持文字子
  频道；官方 bot 每天全群共享约 10 次），因此默认关闭。

### @全体成员为什么加了群管理也不生效

QQ 官方机器人在**群聊场景**实际不支持 `@everyone`：官方格式文档只对“文字
子频道”定义该标签，群消息接口即使接收带 `@everyone` 的内容，也不会产生
@ 效果，与机器人是否被设为群管理员无关。插件会照常发出通知，只是无法真正
@ 到人；建议在 WebUI 保持“通知尝试 @全体成员”关闭。

### 主动推送前提
- QQ 官方适配器的主动推送依赖该群**先与机器人产生过消息**（用于缓存会话
  场景）；插件在收到群消息时会自动注册该群并保持推送目标。
- 若某群从没给机器人发过消息，定时推送可能被平台侧跳过。
- 平台实例 ID（会话前缀，如“爱莉希雅”）由插件**自动获取**：发送时会动态
  查找 `qq_official` 类型平台实例，并把每个群实际来源的实例 ID 记录在该群
  配置中，无需手动填写；WebUI 会显示当前检测到的 ID 供排障。
- 若机器人本次运行期间该群还没发过任何消息，插件会在日志中提示“主动推送
  可能被 QQ 适配器跳过”，请先让群内发一条消息。
- WebUI 群配置里的“测试推送”按钮可随时验证链路：先在群里发一条消息，
  再点击按钮，机器人会立即向该群发送今日比赛早报。
- 首次使用在群内发送 `acmer激活` 激活一次即可，状态会持久保存；
  AstrBot 重启后无需重复触发，群内任意一条消息都会自动重新激活
  （机器人回复激活命令时会缓存该群消息 ID，主动推送更稳定）；
  激活成功后再次发送 `acmer激活` 会被静默忽略，不再回复。

## 5. 数据源与缓存

| 平台 | 来源 | 说明 |
| :--- | :--- | :--- |
| Codeforces | `codeforces.com/api/contest.list` | 官方 API，`phase=BEFORE` |
| 牛客 | `ac.nowcoder.com/acm/calendar/contest` | 牛客比赛日历，抓当前月+下月 |
| AtCoder | `atcoder.jp/contests/` | 官网 Upcoming Contests 赛程表 |
| 洛谷 | `luogu.com.cn/contest/list` | 页面内 `#lentille-context` JSON，无需登录 |

- 内存缓存 5 分钟；`/update`（管理员）可强制刷新。
- 网络超时 10 秒，最多重试 3 次；失败返回友好提示并记录日志。

## 6. 常见问题

**`/update` 提示“此指令仅限管理员”**：管理员列表为空或未包含你的 openid，
到 WebUI 添加后重试。

**插件已安装、后台能配置，但指令/群自动注册都没反应**：这是 AstrBot 的
“可用插件”名单（`plugin_set`）把本插件过滤掉了。检查 AstrBot
**设置 → 插件配置 → 可用插件**是否包含 `acmer_qq_group_bot`（或设为
“全部”），并检查该群/会话级插件开关是否启用了本插件；修改后保存并重载。

**没收到早报/提醒**：依次检查——群是否出现在 WebUI 群列表且已启用；该群
是否给机器人发过消息（主动推送前提）；当天/该时段是否有比赛；提醒开关是否
开启；@全体开启时是否失败降级（会有一条普通通知）。

**日志提示“QQOfficial No cached msg_id ... skip send_by_session”**：这是
QQ 官方适配器的主动推送限制——需要该群在机器人**本次运行期间**发过消息来
缓存会话场景。让群内随便发一条消息后再等待下一个推送周期即可。

**@全体成员没生效**：QQ 官方机器人在群聊的 @全体能力受限，失败后插件已
自动降级为普通通知，并在 6 小时内不再尝试。

**配置改了多久生效**：保存立即生效；定时任务最多 30 秒内按新配置执行。

## 7. 不建议直接改数据库

所有配置应通过 WebUI 修改。直接改 AstrBot 数据库的 KV 记录有一定风险
（格式校验、并发写入），仅在排障时由维护者谨慎操作。
