# acmerQQ群机器人 后台 UI 重设计 · 需求文档

> 状态:**待评审(未实现)**
> 目标版本:1.17.0
> 依据:现有 `pages/settings/index.html`(509 行、单文件原生 JS)与 `main.py` 的 Web API
> **6 项决策已确认(§9),无遗留待确认项**

---

## 1. 背景与现状问题

| # | 问题 | 现状证据 |
| --- | --- | --- |
| P1 | 设置全平铺 | 19 项推送设置塞在「推送设置」一张卡里,无分组、无锚点、无搜索 |
| P2 | 群配置表信息缺失 | 表头只有 群ID/启用/早报时间/赛后赛果 4 列;`push_platforms`、`reminder_enabled`、`activated` 在模型里有但页面看不到、改不了 |
| P3 | 群多时不可用 | 无搜索、无分页、无批量启用/禁用、无批量测试 |
| P4 | 无未保存提示 | 改了不保存就切走没有任何提示;校验失败只在顶部一条 |
| P5 | 无运行状态 | 看不到「最近推送结果 / 失败原因 / 下次推送时间」,只能翻日志 |
| P6 | 绑定数据只能靠指令改 | 后台无法查看/新增/修改/删除账号绑定,只能让用户在群里发指令 |
| P7 | 无备份恢复 | 配置只能一项项手改,没有导入/导出 |
| P8 | 定时推送无法试跑 | 想验证早报/周报/赛果只能等时间点;现有「测试推送」只覆盖早报一项 |
| P9 | 窄屏差 | 表格 + 长行在窄屏横向挤压 |

## 2. 目标

1. **保留**粉紫「PINK PEARL」视觉基调,升级布局与精致度(不换肤)。
2. 改为「**左侧导航 + 分区面板**」,设置按主题分 7 类,每区可独立保存。
3. 群配置升级为可搜索 / 分页 / 批量操作 / 行内编辑 / 单群测试。
4. 新增 4 项能力:配置导入导出、运行状态面板、**账号绑定增删改查 + 群排行只读查看**、定时推送“立即试跑”。
5. **零依赖**:单个 `index.html`,原生 CSS/JS,离线可用,兼容 AstrBot 插件页 bridge。

## 3. 范围

**做**
- 前端页面重写(`pages/settings/index.html`)
- 后端新增接口:概览/日志、绑定**增删改查**、排行只读、立即试跑、导入
- 新增 KV 状态键(推送日志)

**不做 / 不改**
- 不改现有 KV 结构:`admin_users`、`settings`、`groups` 字段与语义原样保留
- 不改现有接口语义:`GET/POST /config`、`POST /test-push` 行为不变
- 不改任何 QQ 指令行为(后台绑定与指令绑定共用同一套存储)
- 不改鉴权体系(沿用 AstrBot bridge 登录态)
- 不引入 CDN / 框架 / 构建步骤
- **不做多语言**(不引入 i18n,也不预留)

## 4. 角色与权限

- 页面只有一种角色:**已登录 AstrBot 后台的管理员**。
- 后台绑定操作与 QQ 群里的「管理员 @代绑定」**同属可信路径**:跳过验证码,但同样受“同一 OJ 账号全局唯一”约束,不会顶掉别人的账号。
- 页面不新增"页内提权"逻辑。

## 5. 功能需求

### F1 布局与导航
- 左侧固定导航,7 个分区:**概览与状态、基础设置、推送设置、群推送配置、账号绑定、群排行、配置备份**。
- 内容区单页切换;URL hash 记忆分区(`#/bindings`),刷新后停留原分区。
- ≤820px 侧栏收为抽屉;顶部工具条含平台实例、未保存计数、导入/导出。

**验收**:7 分区可切换;刷新后仍在原分区;窄屏可操作。

### F2 基础设置
- 管理员列表:添加(支持 `platform_id:uid` 与裸 uid)、移除、重复校验;增删即时保存。
- 展示当前平台实例 ID(只读)+「主动推送需要群内发过消息」说明 + 概览数字。

**验收**:增删管理员即时生效并反馈。

### F3 推送设置(分组)
7 个可折叠分组,每组独立保存:

| 分组 | 字段 |
| --- | --- |
| 早报 | `morning_push_time`、`push_platforms` |
| 赛前提醒 | `reminder_enabled`、`at_all_enabled`(带官方群不支持说明) |
| 每日一题 | `daily_problem_enabled`、`daily_problem_platform`、`daily_problem_count`(1~3,当前 UI 未暴露)、`recommend_enabled` |
| 赛后赛果 | `settle_push_enabled`、`settle_delay_minutes`、`settle_min_participants`、`settle_show_unsolved` |
| 训练周报 | `weekly_report_enabled`、`weekly_report_weekday`、`weekly_report_time` |
| 查询口径 | `recent_contest_days`、`nowcoder_scope` |
| 转图阈值 | `max_plain_text_chars`、`max_plain_text_lines` |

**验收**:19 项设置全部可见可改;范围/默认值与 §6 一致;非法值就地报错。

### F4 群推送配置
- 列:群 ID、平台、**已激活**、启用、早报时间、推送平台、赛前提醒、赛后赛果、操作(测试推送)。
- 搜索(群 ID/平台)+ 分页(默认 20/页)+ 全选当前页 + 批量启用/禁用 + 批量测试(串行,逐条结果)。
- 行内编辑并高亮“已改动”行,支持“还原本行”。

**验收**:100 群不卡;批量测试有逐条反馈;改动行有标记。

### F5 账号绑定(增删改查)★

| 操作 | 入口 | 说明 |
| --- | --- | --- |
| **查** | 列表 | 列:QQ 用户、平台、账号(handle)、昵称、绑定时间、操作。支持按平台筛选 + 关键词(QQ/账号/昵称)搜索 + 分页 |
| **增** | “新增绑定”按钮 | 表单:QQ 用户 ID(必填)、平台(下拉)、账号(必填,支持 用户名/UID/主页链接)、昵称(选填)、归属群(选填,从已注册群选) |
| **改** | 行内“编辑” | 同“增”表单;同一用户同一平台再次保存 = **覆盖/换绑**;保存前若已有绑定,提示“将替换原账号 X”并二次确认 |
| **删** | 行内“删除” + 批量删除 | 二次确认;删除后同步清理该用户该平台的待确认绑定 |

规则:
- 账号标识归一化沿用 `normalize_account_identifier`(与指令一致:CF/AtCoder 支持用户名,牛客/洛谷需数字 UID 或主页链接)。
- 保存前**实时抓取公开资料**校验账号存在;抓不到则该次保存失败并给出平台原因。
- 命中“该账号已绑定他人” → 明确拒绝,**不顶号**。
- 保存/删除成功后,**立即失效群排行缓存**(否则排行还是旧的)。
- 所有后台绑定/解绑操作写审计日志(操作者记为 web 后台)。

**验收**:四条操作全部可用;冲突与非法输入有明确提示;操作后群排行不再显示旧数据。

### F6 群排行(只读)
- 选择群 + 平台,查看排行;默认只读快照,可点“刷新”强制重算。
- 显示“数据可能较旧”标记与平台错误摘要。
- **只读**:不提供任何修改入口。

**验收**:能查看排行;默认不触发全群抓取;刷新按钮生效。

### F7 运行状态面板
- 每群最近一次推送(类型/时间/成功失败/原因摘要)、下次预计推送时间(早报/周报)、平台实例、群数/管理员数、存储后端(SQLite/KV)。
- 数据来自新增只读接口 + 新增 KV 环形日志;支持刷新与空态。

**验收**:能自证“某群某次推送是否成功”,不依赖翻日志。

### F8 立即试跑
- 可选类型:早报(含周榜)、训练周报、赛果(选具体一场)、报名提醒(选具体一场);**仅单群**。
- 触发前校验:群存在/已启用/主动推送会话就绪;不就绪给出原因。
- 结果逐步展示并写入推送日志。
- **试跑不写幂等键**(不挤掉当天正式推送)。

**验收**:试跑可控、不污染正式推送状态。

### F9 配置导入导出
- 导出:`admin_users + settings + groups(可勾选是否含群配置)` → JSON 下载。
- 导入:选文件 → 后端校验并返回**差异预览** → 二次确认 → 落库。
- 默认模式:**覆盖 settings + 合并 admin_users + 覆盖 groups**;页面提供 3 个勾选项可调整。

**验收**:导出的文件可被重新导入且结果一致;非法文件整体拒绝并说明原因。

### F10 保存与校验
- 分区独立保存 + 脏标记 + 离开提示(含绑定/群列表的未保存态)。
- 字段级校验(红框 + 就近文案);保存中禁用 + loading;成功/失败用 Toast。

**验收**:不会“改了忘保存”;失败能定位字段。

### F11 视觉与响应式
- 保留粉紫配色变量,新增层级/间距/圆角/阴影令牌。
- 统一组件:卡片、区块标题、表单行、开关、分段控件、徽章、表格、按钮、Toast、对话框、空态、骨架屏。
- 桌面侧栏常驻;≤820px 抽屉;表格窄屏转卡片行。

**验收**:桌面/窄屏均可完成全部操作。

## 7. 非功能需求

- **兼容**:AstrBot ≥ 4.13;仅用 `ready/apiGet/apiPost/download`,不依赖未公开能力。
- **零依赖/离线**:不引 CDN、不引包管理。
- **性能**:群 200 条内,搜索/分页前端完成;绑定列表一次返回 + 前端筛选(超过 2000 条再改服务端分页)。
- **可用性**:键盘可达、焦点可见;错误就近展示;危险操作二次确认。
- **可维护**:单文件内注释分区,命名与后端字段一一对应。
- **安全**:导入内容经后端白名单校验;页面全部用 `textContent`,杜绝 XSS;绑定写操作受唯一约束保护。

## 8. 总体验收标准

1. 19 项设置 + 管理员 + 群配置(含新增 3 个可见字段)全部可读可写。
2. 账号绑定**增删改查**全部可用;群排行只读可用。
3. 导入导出、运行状态、立即试跑均可用,且不破坏现有接口契约。
4. 分区保存 + 未保存提示 + 字段级校验生效。
5. 桌面与窄屏均可完成全部操作。
6. 现有 QQ 指令与定时推送行为**零回归**。

## 9. 已确认决策(全部确认,无遗留)

| 项 | 决策 |
| --- | --- |
| 视觉风格 | 保留粉紫主题,只升级布局与精致度 |
| 布局结构 | 左侧导航 + 分区面板 |
| 技术栈 | 零依赖:单文件 HTML + 原生 CSS/JS |
| 群配置 | 搜索 + 分页 + 批量启用/禁用 + 批量测试 |
| 推送日志 | 新增 KV 键 `push_log`,环形保留最近 **200** 条(全局,不按群) |
| 绑定数据规模 | 一次性返回 + 前端筛选;超 2000 条再改服务端分页 |
| 导入模式 | 默认「覆盖 settings + 合并 admin_users + 覆盖 groups」,页面给 3 个勾选项 |
| 试跑范围 | 只允许**单群** |
| 多语言 | **不做**(不引入 i18n) |
| 数据操作 | **群排行只读;账号绑定做完整增删改查** |
| 保存方式 | 分区独立保存 + 未保存改动提示 |

## 10. 设计约束备忘(供设计/实现文档遵守)

1. 后台绑定与群指令绑定**共用** `AccountRegistry.save_binding/remove_binding`,不另建存储。
2. 后台绑定同样跳过验证码,但**必须**遵守唯一约束(不顶号)并失效排行缓存。
3. 试跑**不得**写 `morning_*`/`weekly_*`/`settle_*`/`signup_*` 幂等键。
4. 排行默认 `allow_stale=True, force=False`,只有“刷新”才强制重算。
5. 导入必须“预览 → 确认 → 落库”两段式,且经后端白名单校验。
