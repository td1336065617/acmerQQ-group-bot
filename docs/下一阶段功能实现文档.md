## 0. 公共约定（所有功能必须遵守）

### 0.1 幂等键命名

| 功能 | 键 | 语义 |
| --- | --- | --- |
| 赛后赛果 | `settle_<群ID>_<平台>_<contestID>` | 每群每场只推一次 |
| 每日一题 | `daily_<群ID>_<YYYYMMDD>` | 当天同群同题（用于"早报 + 指令"一致性） |
| 训练周报 | `weekly_<群ID>_<ISO周，如 2026-W38>` | 每周每群只推一次 |
| 报名提醒 | `signup_<contestID>_<24h\|2h>` | 每个档位只提醒一次 |

统一规则：**发送成功才写幂等键**；失败不写，下一 tick 自动重试（与现有 `morning_<群ID>_<日期>` 完全一致）。

### 0.2 新配置项落地 6 步（漏一步就等于没做）

1. `main.py` 顶部常量（默认值、上下界）；
2. `get_settings()` 读取 + 校验（越界回退默认）；
3. `_web_config_set()` 写入 + 立即生效（`_settings_cache = None`）；
4. `pages/settings/index.html`：控件 + 初始化 + 保存 payload；
5. `README.md` 配置表 + `docs/CONFIG.md`；
6. `tests/test_main_accounts.py`（或新增）断言读写与非法值回退。

> 参考本仓库已落地的 `nowcoder_scope`（1.12.0）——它的 6 步链路就是模板。

### 0.3 新卡片类型接入 5 步

1. `AccountCardRenderer` 新增 `render_<kind>()`：组装 `source = {"kind": "<kind>", ...}`；
2. 新增 `_<kind>_html()`（HTML 路径，复用 `PLATFORM_COLORS` 与 `mini-*` 样式）；
3. 新增 `_pillow_<kind>()`（Pillow 回退路径，签名与 `_pillow_overview` 一致：`(sections, title, subtitle, note, image_path) -> bool`）；
4. `_estimate_height()` 增加 `kind` 分支（新增 `_<kind>_height()`）；
5. **`CARD_FORMAT_VERSION += 1`**（否则命中旧缓存图）。

### 0.4 降级三原则

- **宁可少推，不推错**：数据不完整就不发（或明确标注口径），不猜、不补零；
- **单点失败不扩散**：一个平台/一个群失败，其他照常；
- **用户可见的降级要有文案**：卡片/消息里写清"数据源"与"缺失了什么"。

### 0.5 日志规范

- 抓取失败：`logger.warning("...：%s", exc)`，含平台、对象标识；
- 节奏类信息（推送成功、幂等命中、缓存命中）：`logger.info`，含群 ID 与关键数值；
- 高频路径（每 tick 检查）不打印 debug 以上日志。

### A1.1 `src/settlement.py`

```python
SETTLE_PLATFORMS = ("codeforces", "atcoder", "nowcoder", "luogu")
SETTLE_MAX_ROWS = 10                 # 卡片每平台最多 10 行

NOWCODER_RANK_SUBMIT_URL = "https://ac.nowcoder.com/acm/contest/rank/submit-list"
CF_STANDINGS_URL = "https://codeforces.com/api/contest.standings"
ATCODER_RESULTS_URL = "https://atcoder.jp/contests/{slug}/results/json"

class SettleRow:

class SettleResult:
```

```python
class SettlementService:
    def __init__(self, plugin) -> None: ...
    async def collect(
        self, platform: str, contest: Contest, members: List[tuple[str, str, str]]
    ) -> Optional[SettleResult]:
        """members = [(user_id, display_name, handle)]，返回 None 表示无人参赛/无可推内容。"""
```

四条平台路径（细节见设计文档 §A1.4/A1.5）：

| 平台 | 请求 | 匹配 | 产出 |
| --- | --- | --- | --- |
| Codeforces | `GET {CF_STANDINGS_URL}?contestId=<id>`（**只带这一个参数**，走 `account_fetcher._cf_json` 复用限速锁） | `rows[].party.members[].handle` 与 handle 集合 `casefold()` 比对 | `rank/user_count(=len(rows))/solved(problemResults 中 points>0 计数)/total_problems/unsolved(未通过的 index 列表)/rated(是否全为 FINAL)` |
| AtCoder | `GET {ATCODER_RESULTS_URL}`（slug 取 `contest.contest_id`） | `UserName`/`UserScreenName` 比对 | `rank(Place)/user_count=len(payload)`；`solved` 缺省为空（可选用 kenkoooo 补，见风险） |
| 牛客 | `GET {NOWCODER_HEAVY_HISTORY_URL}?token=&uid=<uid>&page=1&onlyJoinedFilter=true&searchContestName=&onlyRatingFilter=false&contestEndFilter=true`（**每成员 1 次**，1~3KB） | `contestId == int(contest.contest_id)` 精确匹配 | `rank/user_count/acceptedCount/problemCount` |
| 洛谷 | 无公开榜单 → 用 `get_profile(force=False, detail=True)` 的 ELO 历史判断是否参赛 | — | 不产生行，写进 `extra_note` |

关键实现点：

1. **CF 参数坑**：带 `from/count/showUnofficial` 会被 CF 拒绝（实测错误信息见设计文档附录 A），`_cf_json` 调用时 params 只能有 `contestId`；
2. **CF 重测中判定**：`problemResults[].type == "PRELIMINARY"` → `note` 加"重测中，名次可能微调"；全 `FINAL` → 不加；
3. **牛客必须走 `/acm-heavy/`**（同名 `/acm/` 路径无 rank/ac 字段），请求头沿用 `X-Requested-With` + `Referer`；成员按 uid 请求，`asyncio.Semaphore(RANK_FETCH_CONCURRENCY=8)` 限流，结果按 uid 缓存 30 分钟（`_nowcoder_history_cache`）；
4. **牛客未就绪**：窗口内若该成员历史里查不到该 `contestId` → 视为"未就绪"，返回 `None` 交由上层重试（不写幂等键）；
5. **洛谷**：`extra_note = "洛谷参赛：A、B（该平台不公开名次）"`；无人参赛则不产生 note；
6. 所有平台结果按 `rank` 升序；`rank` 缺失的行排在最后。

### A1.3 推送接线（`main.py` + `src/scheduler.py`）

> ⚠️ **端到端核对时发现的必须修正项（已实现于 `src/settlement.py`）**
> 赛程接口**只返回"未开始"的比赛**（CF 按 `phase=BEFORE` 过滤、AtCoder 只给 upcoming 表、
> 洛谷只保留未来场次），比赛一结束就从列表里消失 → **不能直接从赛程列表挑"刚结束的比赛"**。
> 因此新增"最近比赛记录"机制：
> - `SettlementService.remember_contests()`：每个 tick 把**上一次缓存里的赛程**与**本次抓取的赛程**
>   都记入 `{(platform, contest_id): {name, start, end, url, duration}}`（覆盖"结束前最后一次抓取"
>   与"结束后第一次抓取"两种时序）；
> - `settlement_candidates(platform, now, delay, window_hours=2)`：从记录里挑"刚结束且在窗口内"的比赛；
> - `save/load_recent_contests()`：落盘 `settle_recent.json`（保留 26 小时 / 最多 400 条），
>   **重启后仍能结算"结束前已见过"的比赛**。


```python
# main.py
async def tick_settlements(self, now: datetime) -> None:
    """scheduler 每 tick 调用；内部按群、按平台独立处理。"""
```
处理流程：
1. `groups = await self.get_groups()`；对 `group.enabled and group.settle_push_enabled` 的群；
2. `platforms = group.push_platforms ∩ settings.push_platforms`；
3. 每平台 `contests, err = await self.fetcher.fetch_platform(platform)`（复用 5 分钟缓存、多群共享）；
4. 候选：`end_time` 存在（缺失用 `start_time + duration_minutes`）且 `settle_delay ≤ now - end ≤ 2h`；
5. 幂等键命中即跳过；
6. `members = [(user_id, display, handle)]`：`account_registry.get_group_member_ids(gid)` × `get_all_accounts()` 过滤出该平台绑定者；
7. `result = await self.settlement.collect(...)`；`result is None or not result.rows` → 跳过（不写键）；
8. 渲染卡片：`_render_overview_card` 等价入口（新增 `_render_settlement_card`），失败回退纯文本（`send_notification`）；
9. 发送成功 → 写幂等键 + `logger.info`。

`src/scheduler.py` 只增加薄钩子（照现有 `warmer` 写法）：

```python
for hook_name in ("tick_settlements", "tick_weekly_report", "tick_signup_reminders"):
    hook = getattr(self.plugin, hook_name, None)
```

### A1.5 测试（`tests/test_settlement.py`，12 例）

1. 候选窗口：`end_time = now-11min` 命中；`now-9min` 未到；`now-3h` 超窗；
2. `end_time` 缺失 → 用 `start + duration_minutes` 推算；
3. 幂等：同群同场第二次调用不发（monkeypatch 计数）；
4. 多群共享：两个群同一场 → 底层抓取只发生 1 次；
5. CF：**params 只有 contestId**（断言传给 `_cf_json` 的字典）；
6. CF：`solved` 计数＝`points>0` 的 problemResults 数；`unsolved` 为未通过 index；
7. CF：含 `PRELIMINARY` → `note` 含"重测中"；
8. AtCoder：`Place` 映射名次；无匹配成员 → 返回 None；
9. 牛客：命中 `contestId` → rank/accepted/userCount 正确；未命中 → 返回 None（触发重试）；
10. 牛客：请求 URL 必须是 `/acm-heavy/`（字符串断言，防回归）；
11. 洛谷：只产出 `extra_note`，不产生行；
12. 无人参赛 → `collect` 返回 None，主流程不推送。

### A1.6 验收标准

- 用**真实已结束比赛**手动跑一次 `tick_settlements`，群里收到卡片，`#名次/参赛人数 · 通过题数` 与官网一致；
- 同一场比赛第二次 tick 不再推送；
- CF 未重测完的比赛，卡片带"重测中"文案；
- 断网/接口 500 → 无推送、无异常堆栈、下一 tick 重试。

```python
RATING_TO_DIFFICULTY = [(800, 0), (1000, 600), (1200, 1000), (1400, 1400), (1700, 1800), (2000, 2200), (2400, 2600)]
# 群/个人 Rating → 目标难度区间（band index ±1）

class ProblemService:
    def __init__(self, plugin) -> None: ...
    def nowcoder_pool(self) -> List[Problem]: ...
    async def ensure_index(self, platform: str) -> int: ...      # CF/洛谷落盘缓存，TTL 7 天
    def band_of(self, rating: Optional[int]) -> int: ...
    def pick_daily(self, *, group_id: str, day: str, rating: Optional[int],
                   exclude: Set[str], seed_extra: str = "") -> Optional[Problem]:
        """确定性抽题：候选集 → 按 canonical tag 轮换过滤 → 以 sha1(f"{group_id}:{day}:{seed_extra}") 取模。"""
    def recommend(self, *, profile, solved: Set[str], weak_tags: List[str],
```

**确定性抽题（可复现）**
```python
candidates = [p for p in pool if p.difficulty and p.problem_id not in exclude
              and band - 1 <= self.band_of(p.difficulty) <= band + 1
              and rotate_tag in p.tags]
if not candidates:                      # 知识点过滤后为空 → 放宽到不限知识点
    candidates = [...]
digest = hashlib.sha1(f"{group_id}:{day}:{seed_extra}".encode()).hexdigest()
index = int(digest[:8], 16) % len(candidates)
return sorted(candidates, key=lambda p: (p.difficulty, p.problem_id))[index]
```
- `rotate_tag = CANONICAL_TAGS[date.weekday() % len(CANONICAL_TAGS)]`——同一天所有群共用轮换标签，但题目按群 ID 区分；
- `exclude`：群内成员已通过题（来自 A2.1 的 `solved_problem_ids`，取并集，上限保护 5000）。

**推荐补题**
```python
weak = [t for t, _ in sorted(category_counts.items(), key=lambda kv: kv[1])[:3]]   # 通过数最少的知识点
picks = pool 过滤 → 未通过 → 难度∈[个人中位档-1, +1] → tags ∩ weak → 按 (难度升序, 命中 weak 数降序) 取 3
```

### 3.2 本轮评审发现的 4 处设计问题与修正（已回写设计文档）

| # | 原设计 | 问题 | 修正 |
| --- | --- | --- | --- |
| 1 | A1.8 写"平台名次不可得（牛客/洛谷）" | 牛客侦察已完成，名次与通过题数可得 | 改为"仅洛谷不可得" |
| 2 | A2 只说牛客要补 `solved_problem_ids`，CF/AtCoder 列为"Phase 2" | 既然四平台同步接题库，"未通过"判断是推荐的前提 | CF/AtCoder 同批补 `solved_problem_ids`；并**明确 `ANALYSIS_CACHE_VERSION 4→5`** |
| 3 | A2 知识点轮换直接用平台原始标签 | 牛客/洛谷是中文、CF 是英文，跨平台无法统一轮换与推荐 | 新增 `src/problem_tags.py` 做规范标签归一 |
| 4 | A3 说"数据全部本地、零额外抓取"，并用分析缓存里的 `activity_daily` | `activity_daily` 只在**详细资料**（含提交扫描，CF 上限 5 万条）时产生，周报若依赖它会极贵 | 新增轻量 `weekly_stats`（只取近 7 天，CF 1 请求/成员），牛客/洛谷本次不统计活跃并如实标注 |

### 3.3 被否方案与理由

| 方案 | 否掉的理由 |
| --- | --- |
| A1 等 Rating 结算后推（原设计） | CF 需等系统重测、牛客固定次日 00:00 → 推送延迟数小时~次日，失去时效；评审已明确"卡不带评分变化" |
| A1 用牛客比赛页 `submit-list` 算名次 | 该接口只给原始提交（无现成名次），需自行实现周赛/ACM/OI 各赛制排名规则，脆弱且易错 |
| A2 用随机数抽题 | 早报与指令、以及多群之间的结果不可复现，用户会看到"同一天两个答案" |
| A3 复用详细资料的分析缓存 | 会触发 CF 5 万条提交扫描（单成员可耗时数十秒） |
| A4 用 XCPC Link 做报名提醒 | 线下赛赛程没有机器可读的报名截止字段 |

### 3.4 明确"不承诺"的边界

- **不承诺**培训级精确名次：CF 重测后名次可能微调，卡片标注"重测中"且不补推；
- **不承诺**洛谷名次（计分板需登录）；牛客/洛谷的"活跃天数"不在周报统计内；
- **不承诺**每日一题一定"最适合"：它是按难度档 + 知识点轮换的可复现抽题，不是个性化推荐算法；
- **不承诺**比赛取消/改期场景的准确提醒（以官方赛程为准）。
