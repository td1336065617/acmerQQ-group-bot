# acmerQQ群机器人 · 插件开发规范

> 状态：**活文档**。每次遇到问题（线上故障 / 测试暴露 / 评审发现 / 用户反馈）都必须回填本文件，
> 见 **§3 问题回填机制（强制）**。回填记录见 **§11 案例库**。
> 首次成文：2026-09-27（当日发生 2 起线上事故、共修复 6 类缺陷后制定）。

## 1. 适用范围

适用于本插件仓库（main.py / src / pages / tests / docs）以及配套的运维脚本（工作区 tools/）。
新增插件同样适用：把本文件复制到新仓库 docs/ 下并沿用 §3 的回填要求。

## 2. 三条底线原则

1. **真实契约优先**：调用点与定义必须真实一致——函数归属（模块级 vs 方法）、参数个数、**参数顺序**、
   关键字名。测试里的 stub / 假服务不得比真实类「更全」，否则会掩盖这类错误。
2. **失败必须可见**：任何「返回 None / 吞异常 / 静默降级」的分支都必须留痕（日志或计数）。
   线上不允许出现「行为变了但日志里什么都没有」。
3. **共享状态谨慎**：轮询键（poll_key）、群级去重键、渲染缓存、平台会话场景都是跨群/跨平台共享的，
   改动必须考虑「多群同 tick」「跨群污染」「终态传染」三种情形。

## 3. 问题回填机制（强制）

**触发条件**：任何一次问题被确认（线上故障、测试失败、代码评审、用户反馈、自动检查报警）**都要**在本规范里
新增一条回填记录——不允许只修代码。

**回填内容（缺一不可）**：

1. 记录到 §11 案例库，编号递增（CASE-xx），字段：日期 / 版本 / 现象 / 根因 / 影响面 / 修复 / **新增防线**；
2. 若该问题暴露出一条**新规则**，把它写进 §4~§8 对应章节（规则要写成可执行的动作，不写口号）；
3. 若该问题可以用**自动化检查**覆盖，则补脚本或用例，并把命令写进 §10；
4. 若属于发布流程问题，更新 §8/§9；
5. 回填与代码修复**同一个提交**或紧邻提交完成，且 CHANGELOG 里引用案例编号。

**判定标准（自问三句）**：这条问题以后还会不会以别的形式再出现？我加的防线能不能自动拦住它？
如果不能自动拦住，我有没有在 §11 里写清「人工检查点」？

## 4. 编码规范

- 4.1 **函数归属**：模块级工具函数不要挂在 self 上调用。跨模块函数用 `from ... import` 引入后直接调用；
  只有类的方法才允许 `self.x.method(...)`。（案例 CASE-01）
- 4.2 **参数顺序即契约**：当函数会被回调式调用（如 `_render` 的 `fallback(*args, image_tmp)`）时，
  必须在 docstring 里写明顺序约束，并在调用处避免位置歧义；新增参数优先放到**关键字参数区**。（案例 CASE-02）
- 4.9 **改名/删除方法前必须全局搜引用**：`self.X(...)` 里的 X 若在插件内从未定义，运行时必然 AttributeError，
  且很容易被 `try/except` 吞成一条 warning（用户侧表现为功能静默失效）。已由 `tools/plugin_argscan.py` 强制。（案例 CASE-10）
- 4.3 **新增参数要全局搜调用点**：`grep -rn "函数名(" --include=*.py` 确认每一个调用点都已适配；
  直接调用点建议改用关键字传参，避免以后顺序变化被静默坑到。
- 4.4 **None 语义**：返回 None 必须代表明确的「无结果」，且调用方必须能区分「无结果」与「失败」；
  失败路径不得复用 None。
- 4.5 **异常处理**：只吞掉「确实无关紧要」的异常，且必须打日志（warning 起）。
  带节流的告警优先用 `_warn_throttled`，避免刷屏。
- 4.6 **日志级别**：用户可感知的降级（如卡片改文字）→ WARNING；状态迁移（如赛果判定完成）→ INFO 且只打一次；
  周期性复评 → DEBUG。
- 4.7 **类型与默认值**：公共函数参数尽量给默认值；必填的关键字参数（kw-only）要显式声明。

## 5. 测试规范

- 5.1 **契约测试**：新增/修改跨模块调用后，必须有用例覆盖「真实类具备被调用的方法/签名」
  （参考 tests/test_settlement_contract.py）。
- 5.2 **禁止只 stub 入口**：渲染、解析、序列化这类「输入正确才成功」的路径，用例必须至少有一条走**真实实现**
  （参考 tests/test_settlement_card.py 的渲染契约用例）。（案例 CASE-02/CASE-06）
- 5.3 **假服务诚实性**：测试用 fake 不得定义真实类没有的方法；已有守卫用例强制（案例 CASE-05）。
- 5.4 **共享状态用例**：涉及 poll_key / 群级去重 / 缓存的改动，必须补「多群同 tick」「另一个群不受影响」的用例。
  （案例 CASE-04）
- 5.5 **参数顺序用例**：对回调式/位置敏感的函数，用例要按**调用方真实形状**传参，而不是按签名直觉传参。
- 5.6 **fixtures**：真实数据统一放 tests/fixtures/*.json.gz（AtCoder 半截/完整榜单、CF standings/ratingChanges/status），
  优先用真实数据回放，而不是构造理想数据。
- 5.7 **用例命名**：`test_<模块>_<被验证的约束>`，被验证的是「约束」而不是「函数名」，便于回归定位。

## 6. 渲染与外部依赖规范

- 6.1 渲染入口（`render_*`）失败时必须返回 None，**并且**在渲染器内部打 WARNING（含最后一次异常）；
  调用方在降级发文字时要打节流告警。（案例 CASE-03）
- 6.2 渲染产物检查：调用方必须校验「路径存在且大小 > 0」，不能只看返回值非空。
- 6.3 新增渲染参数时同步更新：HTML 路径、Pillow 兜底路径、纯文本兜底路径**三处**，并各写一条断言。

## 7. KV / 持久化规范

- 7.1 写 KV 的 `updated_at` 一律用 `datetime.strftime`（**不要用 time.strftime**，glibc 不支持 %f，会写入字面量）；
  写前自检可解析。（案例 CASE-07）
- 7.2 幂等键结构：`{state: pushed, pushed_at, rows, complete, unofficial_count}`；跳过类标记：
  `{skipped: true, members: <成员指纹>, ts}`——带指纹才能在「成员变化」时自动重新评估。
- 7.3 轮询状态字段：state / attempts / samples / next_poll_at / ready_at / ready_logged / abandoned_reason；
  新增字段要考虑旧数据缺省（默认值兜底，不要求迁移脚本）。
- 7.4 终态语义：PUSHED / ABANDONED 为终态；ABANDONED 要区分 `no-participants`（静默）与判定 reason（要提示）。

## 8. 发布与部署规范

- 8.1 任何对外可见的改动都要：升 metadata.yaml 版本 + 写 CHANGELOG（含 🚨/🐛/⚙️/✅ 分节）+ 打 tag + 建 Release；
  CHANGELOG 里要引用本规范的案例编号（若该版本是修问题）。
- 8.2 发布前必须依次通过：全量用例 → `tools/plugin_argscan.py` → `tools/plugin_settings_crosscheck.py` →
  `tools/check_inline_js.py` / `check_page_contract.py`（改了页面时）。
- 8.3 部署脚本（tools/settle_strict_deploy.sh）：默认**保留**当前严格模式开关（读取当前值→部署后原样恢复），
  需要强制关闭用 `--strict-off`；备份路径必须打印出来。（案例 CASE-08）
- 8.4 涉及行为开关的部署，先「安全装载（功能开关关闭）」→ 观察 → 再灰度开启；回滚路径写进 CHANGELOG。

## 11. 案例库（回填区，按时间追加）

### CASE-01 模块级函数被当方法调用（1.20.5）
- 现象：`AttributeError: SettlementService has no attribute next_poll_delay_minutes`，tick 每 30 秒崩一次，持续 9 小时（469 次），期间所有赛果卡停发。
- 根因：该函数是 src/settlement.py 的**模块级函数**，调用点写成了 `self.settlement.next_poll_delay_minutes(...)`。
- 影响面：等待路径（牛客/AtCoder/洛谷）+ 同 tick 所有结算（异常中断整个 tick_settlements）。
- 修复：改为直接调用模块级函数。
- **新增防线**：tests/test_settlement_contract.py（扫描 main.py 全部 `self.settlement.X` 断言真实存在 + 真实 service 走等待路径）；tools/plugin_argscan.py 的专项规则。

### CASE-02 Pillow 兜底参数顺序错位（1.20.8）
- 现象：赛果卡自 1.20.0 起静默变成**纯文字**，且日志里没有任何错误；同时生产根目录出现 56 KB 的 `打星` 文件。
- 根因：`_render` 以 `fallback(*fallback_args, image_tmp)` 调用（输出路径永远最后），而 `_pillow_settlement` 签名里 `image_path` 排在 `unofficial_label` 之前 → 字符串 `打星` 被当成输出路径。
- 修复：签名改为 `(..., unofficial_label, image_path)`，docstring 写明顺序契约；既有直接调用改关键字传参。
- **新增防线**：渲染契约用例 2 条（按 `_render` 真实形状传参 / 强制走 Pillow 兜底）；§6.1、§6.3。

### CASE-03 静默降级不留痕（1.20.9）
- 现象：CASE-02 在线上「卡片变文字」两小时无人察觉。
- 根因：`_render` 对每个渲染器 `except Exception` 后直接 `return None`；调用方也没报警。
- 修复：渲染全失败打 WARNING（含最后异常）；`_push_settlement` 改发文字时按平台节流告警。
- **新增防线**：§2.2、§4.5、§6.1、§9 的「新增降级告警必须为 0」。

### CASE-04 共享轮询键上的节流误伤推送（1.20.7）
- 现象：1.20.6 上线后，同一 tick 里只有第一个群能推卡，其余群要等下一个 30 分钟窗口（AtCoder/洛谷窗口内可能永远轮不到）。
- 根因：READY 状态写入 `next_poll_at=+30 分钟`，而 poll_key 是**跨群共享**的；早退逻辑对 READY 也返回 wait。
- 修复：READY 早退改为放行（只节流探测，不节流推送）。
- **新增防线**：多群同 tick 各自推卡用例；§2.3、§5.4。

### CASE-05 假服务掩盖真实接口差异（1.20.6）
- 现象：CASE-01 上线前 455 个用例全绿。
- 根因：两个测试 fake 都定义了真实 `SettlementService` 没有的方法，掩盖了调用点错误。
- 修复：清理虚构方法。**新增防线**：fake 诚实性用例（fake 不得定义真实类没有的方法）；§5.3。

### CASE-06 只 stub 入口导致兜底路径零覆盖（1.20.8）
- 现象：`_push_settlement` 的用例 stub 掉了整个渲染入口，兜底参数问题永远测不到。
- 修复：新增走真实 `render_settlement` / `_pillow_settlement` 的用例。**新增防线**：§5.2。

### CASE-07 运维脚本写入脏时间戳
- 现象：`settings.updated_at` 被写成 `2026-09-27 11:55:08.%f`（字面量）→ AstrBot 解析失败 → `get_settings` 每 tick 报错，赛果/周报巡检空转。
- 根因：脚本用了 `time.strftime(...%f)`，glibc 的 strftime 不支持 %f。
- 修复：改用 `datetime.strftime` + 写入前自检。**新增防线**：§7.1、verify 脚本的全表时间戳检查。

### CASE-08 部署脚本改写行为开关
- 现象：部署（安全装载）会把 `settle_strict_enabled` 强制写成 false，导致灰度被静默关闭。
- 修复：部署前读取当前值，部署后原样恢复；新增 `--strict-off` 显式关闭。**新增防线**：§8.3、§9 的开关一致性断言。

### CASE-10 调用 self 上不存在的方法（被 try/except 吞掉）+ 预览被慢网络挂住（1.20.11）
- 现象：WebUI「测试推送」点了没反应；日志里只有一条 warning「构建测试推送周榜失败」，
  异常为 AttributeError: AcmerGroupBot has no attribute build_weekly_boards_text。
- 根因（两层）：
  1) build_test_text 调用了 1.11.0 就被 push_weekly_boards（图片）取代的 build_weekly_boards_text，
     该名字在插件内**从未定义**（同类 CASE-01，但这次是名字根本不存在）；
  2) 预览会**顺序**抓 4 个平台，CF 网关 504 时后台请求被挂住 → 前端表现为「没反应」。
- 影响面：测试推送/试跑预览；周榜文字部分自 1.11.0 起一直缺失（被吞成 warning，无人察觉）。
- 修复：删除不存在的调用（周榜本就由 push_weekly_boards 以图片追加）；预览改为**并发 + 硬超时**
  （整体 12s / 单平台 6s），超时提示「赛程数据正在刷新」而不是挂住。
- **新增防线**：用例 3 条（源码守卫不得出现该方法名 / 抓取卡住时预览 2s 内返回 / 正常路径展示比赛）；
  tools/plugin_argscan.py 新增规则「self.X(...) 但插件从未定义 X」（基类白名单 get_kv_data / put_kv_data）。
