# acmerQQ群机器人：管理员 @代绑定 实现方案

> 状态：**已实现（v1.16.0）**
> 目标：管理员在群内 `@某成员 绑定cf <账号>`，直接把账号写入被 @ 成员的绑定表，
> **跳过验证码**（管理员代操作，属于可信路径）。
> 原则：不改动任何现有指令行为；复用已验证的 @ 解析与原子绑定存储；先出设计、后实现。

---

## 0. 需求

- 触发者：管理员（`admin_users` 命中）。
- 目标：被 @ 的群成员（唯一、非机器人）。
- 动作：管理员指定平台 + 账号，直接绑定到**目标成员**名下，不走"验证码写入公开资料 → 确认绑定"两步。
- 典型用法：

```
@小明 绑定cf jiangly
@小明 绑定牛客 12345678
@小明 绑定洛谷 123456
@小明 绑定atcoder tourist
```

## 1. 现状调研

### 1.1 用户自主绑定全链路（必须先看懂）

| 阶段 | 函数 | 关键行为 |
| --- | --- | --- |
| 入口 | `_reply_account_bind`（main.py:1512） | 取发送者 `sender_id` → 抓公开资料 `get_profile(force=True)` → `create_pending(user_id, platform, profile, group_id=当前群)` 生成 `ACM-XXXXXXXX` 验证码 → 提示用户把验证码写进平台公开字段 |
| 确认 | `_reply_account_confirm`（main.py:1576） | `get_pending` 取待确认 → 重新抓资料 → `_account_verification_value` 读校验字段 → `token_matches` 比对 → `save_binding(...)` |
| 解绑 | `_reply_account_unbind`（main.py:1732） | `remove_binding(user_id, platform)` |

`_reply_account_confirm` 保存绑定时（main.py:1703）：

```python
await self.account_registry.save_binding(
    user_id, platform, profile,
    group_id=group_id,                     # 发起群 / 确认群
    qq_name=self._event_display_name(event)  # 绑定者（=发送者）昵称
)
self._invalidate_all_rank_cache()
await self._record_profile_metric(user_id, profile)
```

> **重要对照**：`qq_name` 取的是"发送确认的人"的昵称，因为自主绑定里发送者 == 绑定者。
> **代绑定里发送者是管理员、绑定者是目标成员，二者不同**，这里不能照抄（见 §4-3）。

### 1.2 存储层

- 门面：`src/account_registry.py::AccountRegistry.save_binding`（第 187 行）。
  - 启用 SQLite 时走 `AccountStore.save_binding_atomic`，并对 KV 双写；
  - 未启用时走 `_kv_save_binding`。
- 唯一约束：`CREATE UNIQUE INDEX uq_accounts_platform_handle ON accounts (platform, lower(platform_user_id))`
  → 同一 OJ 账号（平台 + 小写 platform_user_id）**全局只能属于一个 QQ 用户**。
- 冲突语义：两个实现都会在"该账号已绑定他人"时抛 `ValueError("这个平台账号已经绑定到其他 QQ 用户")`；
  `save_binding_atomic` 用 `BEGIN IMMEDIATE` + 拿锁后重查，避免并发 REPLACE 顶号。
- `group_id` 非空 → 同一事务里写 `group_members(enabled=1)`，即自动加入该群排行。
- 同目标同平台再次保存 = **覆盖**（`ON CONFLICT(user_id, platform) DO UPDATE`）。

### 1.3 @ 识别现状（可直接复用）

`_mentioned_profile_target`（main.py:869）已经处理好所有通道差异：

- 仅群聊生效（`get_group_id()` 非空）；
- 兼容 QQ 官方 `raw_message.mentions`、AstrBot `At` 组件、`<@id>` / `[CQ:at,qq=]` 文本；
- `_self_id_candidates`（main.py:993）过滤 `@机器人` / `is_you`；
- `_mention_user_id` 过滤 `all`/`everyone`，`_mention_display_name` 取昵称；
- 去重后**恰好一个目标**才返回，多目标 / 零目标返回 `None`；
- 从原文剥离 `<@id>`、`[CQ:at,...]`、`@昵称`（用 `re.escape`），得到指令剩余文本。

但它目前**只对 `MENTION_PROFILE_COMMANDS`（战绩/查询战绩/战绩卡/资料卡/账号）放行**，
`@某人 绑定cf xxx` 会被它判为 `None`，随后在 `on_message` 里因为 `ACCOUNT_BIND_RE` 锚定 `^`
匹配不到而**静默丢弃**——这正是新功能的接入点。

调用位置：`on_message`（main.py:4514）第 4521-4530 行。

### 1.4 管理员体系

- `_is_admin`（main.py:586）读 KV `admin_users`，用 `platform_compat.admin_entry_matches`
  支持 `platform_id:uid` 精确匹配或裸 uid，兼容官方 openid / OneBot QQ 号。
- 现有管理员指令 `_update`（main.py:4483）在函数开头判断 `_is_admin`，不满足回"此指令仅限管理员"。

## 2. 交互设计

### 2.1 命令形态

**推荐**：`@某人 绑定cf <账号>` —— 与自助绑定同一套平台别名与提示文案，记忆成本最低。

- 平台别名：`cf/codeforces`、`nk/牛客/nowcoder`、`lg/洛谷/luogu`、`atc/atcoder`。
- 账号：用户名 / UID / 平台主页链接（与自主绑定完全一致，交由 `normalize_account_identifier` 归一化）。
- 仅群聊有效；私聊 `绑定cf xxx` 仍是**本人自助绑定**，不受影响。

> 备选（见 §5 决策点 A）：使用显式前缀 `@某人 代绑定cf <账号>`，语义更独立，
> 但用户需要多记一个词。二者实现成本相同，可先用 `绑定`，后续按需加别名。

### 2.2 回复文案

| 场景 | 文案（示意） |
| --- | --- |
| 成功 | `✅ 已将 @小明 绑定 Codeforces 账号 jiangly（管理员操作）` + 排行归属提示 |
| 覆盖 | 追加 `已替换原有绑定：old_handle` |
| 目标无昵称 | 用 `该成员`，账号仍以 handle 展示 |
| 账号冲突 | `⚠️ 这个 Codeforces 账号已经绑定到其他 QQ 用户，无法代绑定` |
| 账号不存在/非法 | `⚠️ Codeforces：<平台错误信息>`（复用 `_account_error_text`） |
| 非管理员 | `此指令仅限管理员`（与 `_update` 一致） |

### 2.3 菜单

`MENU_TEXT` 的「🌙 仅管理员」区增加一行：

```
• @某人 绑定cf/牛客/洛谷/atcoder <账号> ─ 管理员代绑定（跳过验证码）
```

## 3. 详细设计

### 3.1 重构 @ 解析（低风险，行为不变）

把 `_mentioned_profile_target` 内部逻辑抽成两个**无指令语义**的纯函数，供两处复用：

```python
@classmethod
def _collect_mention_targets(cls, event) -> list[dict]:
    """收集唯一的非机器人被 @ 目标；群聊之外、@all、多目标返回 []。"""

@staticmethod
def _strip_mention_text(raw_message: str, target: dict) -> str:
    """从原文剥离 <@id> / [CQ:at,qq=] / @昵称，返回指令剩余文本。"""
```

`_mentioned_profile_target` 改为：`collect -> len!=1 return None -> strip -> normalize_command
-> 命中 MENTION_PROFILE_COMMANDS 且不在 SELF_ONLY -> 返回 target`。
**要求逐字保持现有返回结构与判断顺序**，用 `tests/test_main_accounts.py` 现有用例锁死。

### 3.2 新增代绑定识别

```python
@classmethod
def _mentioned_admin_bind(cls, event, raw_message) -> Optional[dict]:
    targets = cls._collect_mention_targets(event)
    if len(targets) != 1:
        return None
    remaining = cls._strip_mention_text(raw_message, targets[0])
    match = ACCOUNT_BIND_RE.match(remaining)      # 复用既有正则，保留账号大小写
    if not match:
        return None
    platform = normalize_platform(match.group(1))
    if not platform:
        return None
    return {
        "user_id": targets[0]["user_id"],
        "display_name": targets[0]["display_name"],
        "platform": platform,
        "identifier": match.group(2).strip(),
    }
```

要点：
- 先剥离 @，再匹配 `ACCOUNT_BIND_RE`，**不能**拿含 `<@..>` 的原文匹配；
- 保留 `identifier` 原始大小写，归一化交给 `normalize_account_identifier` / `get_profile`；
- 返回 `None` 时完全交回原有分发，不改变任何既有行为。

### 3.3 接入 `on_message`

在现有 `mention_target` 分支**之后**、`if not message_str: return` **之前**插入：

```python
admin_bind = self._mentioned_admin_bind(event, raw_message)
if admin_bind is not None:
    async for result in self._reply_admin_bind(event, admin_bind):
        yield result
    return
```

顺序理由：`@某人 战绩` 已被上一分支消费，不会落到这里；两句指令集合不相交。

### 3.4 新增 `_reply_admin_bind(event, bind)` 流程

```
1. if not await self._is_admin(event): 回“此指令仅限管理员”; return
2. target_id = bind["user_id"]；group_id = 当前群
3. identifier 归一化；非法 → 平台通用“标识格式不正确”提示；return
4. profile = account_fetcher.get_profile(platform, identifier, force=True)
   AccountFetchError → self._account_error_text(...); return
   其它异常 → 同样转为用户可见错误；return
5. old = get_user_accounts(target_id).get(platform)         # 仅用于“覆盖”提示
6. save_binding(target_id, platform, profile,
                group_id=group_id,
                qq_name=bind["display_name"])               # ← 必须是被 @ 人的昵称
   ValueError → “该账号已绑定其他 QQ 用户”; return
   其它异常 → “绑定保存失败，请稍后重试”; return
7. self._invalidate_all_rank_cache()
   await self._record_profile_metric(target_id, profile)     # ← 目标 user_id
8. logger.info("管理员 %s 在群 %s 代绑定用户 %s 的 %s 账号 %s",
               admin_id, group_id, target_id, platform, profile.handle)
9. 回复成功 / 覆盖提示 / 排行归属提示
```

**不调用** `create_pending` / `get_pending` / `token_matches` / `_account_verification_value`：
代绑定是可信路径，不生成也不需要验证码；也不应产生残留 pending 记录。

**不调用** `set_user_display_name`：它会按目标 user_id 写全部平台昵称，但来源是管理员昵称，错误。

### 3.5 存储层

**无需改动**。直接复用 `save_binding` 的原子路径与 KV 回退，唯一索引天然防止"顶号"，
`group_id` 顺带完成"目标加入当前群排行"。

## 4. 防 BUG 清单（实现时必须逐条核对）

1. **权限先于写入**：`_is_admin` 必须在 `get_profile` 之前判断，避免非管理员触发抓取/写库。
2. **目标唯一且非机器人**：复用 `_collect_mention_targets`，`@all`/多 @/仅 @机器人 一律不进入代绑定。
3. **`qq_name` 用被 @ 人昵称**，绝不能沿用 `self._event_display_name(event)`（那是管理员），
   否则排行榜会把管理员的昵称挂到目标账号上——本功能最容易踩的坑。
4. **账号冲突靠原子写**：不要先 `get_user_accounts` 判冲突再写（存在 TOCTOU 竞态）；
   直接调用 `save_binding` 并捕获 `ValueError`，提示"已绑定其他 QQ 用户"。
5. **覆盖语义**：同目标同平台再次代绑定是覆盖，不是报错；用第 6 步前的旧值给"已替换"提示。
6. **`group_id` 副作用**：传当前群会让目标自动进本群排行；若目标曾"退出群排行"，
   `save_binding_atomic` 会重新 `enabled=1`。需在文档/回复中明示（见 §5 决策点 B）。
7. **缓存失效**：绑定后必须 `_invalidate_all_rank_cache()`，否则群排行仍显示旧数据。
8. **快照归属**：`_record_profile_metric(target_id, profile)` 用目标 id，不能用管理员 id。
9. **私聊不误判**：`_collect_mention_targets` 依赖群号，私聊返回 []；私聊 `绑定cf xxx` 仍走自助绑定。
10. **重构零回归**：`_mentioned_profile_target` 的行为必须由现有测试逐条锁死；不要顺手改判断顺序。
11. **剥离后再匹配**：`ACCOUNT_BIND_RE` 锚定 `^`；必须先 `_strip_mention_text`，不能匹配原文，
    否则 `@昵称` 里的字符会干扰（现有剥离已对昵称做 `re.escape`，继续保持）。
12. **不要自拼 URL**：账号归一化统一交给 `normalize_account_identifier` / `get_profile`，
    兼容用户名、UID、主页链接三种形态。
13. **错误一律转文案**：`AccountFetchError` 走 `_account_error_text`；任何异常都不能把堆栈发到群里。
14. **存储故障兜底**：`save_binding` 内部已对 SQLite 故障回退 KV，上层仍需 `try/except` 给反馈。
15. **幂等**：同一账号重复代绑定不报错，走覆盖并成功。
16. **正则安全**：昵称/账号不进入正则；剥离 @昵称时保持 `re.escape`。
17. **日志可审计**：记录 admin/target/platform/handle；本功能无 token，不涉及验证码泄露。
18. **版本口径**：不触碰卡片格式/分析缓存，无需提升 `CARD_FORMAT_VERSION` / `ANALYSIS_CACHE_VERSION`。

## 5. 决策点（需拍板）

| # | 决策 | 建议 |
| --- | --- | --- |
| A | 关键字用 `绑定` 还是 `代绑定` | 先用 `@某人 绑定cf <账号>`（菜单一致）；可加 `代绑定` 作为别名 |
| B | 是否自动把目标加入当前群排行（含覆盖"已退出"） | 建议加入（管理员显式操作），并在回复中说明 |
| C | 是否允许管理员 @ 自己 / @ 已在群成员 | 允许；@ 自己等价于自助绑定的快捷方式，无副作用差异 |
| D | 是否同步提供 `@某人 解绑cf` | 建议同批次提供，形成闭环；不在本需求内可后置 |
| E | 非管理员误用回复 | 回复"此指令仅限管理员"（与 `_update` 统一），不静默 |
| F | 账号已被他人绑定时是否"强制顶号" | **不做**；保持唯一约束，提示管理员先解绑 |

## 6. 测试计划

新增 `tests/test_admin_bind.py`（或并入 `test_main_accounts.py`），至少覆盖：

**解析层**
1. QQ 官方 `mentions` + `绑定cf demo` → 正确 target/platform/identifier。
2. AstrBot `At` 组件通道。
3. `<@id>` / `[CQ:at,qq=]` 文本通道。
4. `@all` → 不触发。
5. 多个被 @ → 不触发。
6. 仅 @机器人 → 不触发。
7. 非绑定后缀（`@某人 战绩`）→ 不误入代绑定，原路径仍生效。

**权限与流程层**
8. 非管理员 → 回"此指令仅限管理员"，`save_binding` **未被调用**。
9. 管理员成功 → `save_binding` 的 `user_id` 是目标、`qq_name` 是目标昵称、`group_id` 是当前群。
10. 覆盖场景 → 回复含"已替换"，成功。
11. 冲突 `ValueError` → 回复冲突文案，不写缓存失效。
12. 非法 identifier / 抓取失败 → 各自文案，不调用 `save_binding`。
13. 私聊 → 不触发代绑定。
14. 回归：自助绑定三步（绑定/确认/解绑）、`@某人 战绩` 全部不受影响。

**质量门**
- `pytest tests -q` 全绿（只增不减）；
- `ruff check --select F,E9` 无新增问题。

**真机核对（P4）**
- QQ 官方通道、OneBot 通道各跑一次 `@成员 绑定cf <真实账号>`，核对：
  数据落库、目标 `qq_name`、目标进入群排行、排行缓存刷新、错误路径文案。
